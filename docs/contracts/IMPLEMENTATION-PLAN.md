# Ordered alignment plan — Phase 1

This phase changes the contract, documentation generation and validation only. Implement subsequent slices in the existing Go backend with SIHP's typed DTO/interface → implementation → explicit router composition flow. Every completion claim needs actual route/interface/DTO and relevant behavior tests. Current source session code is inventory, not the Phase 1 target.

1. **Adopt the Phase 1 boundary.** Use the 29-operation canonical OpenAPI and current primary contract. Roles are manually assigned, exactly one per account; backend permissions are fixed. Employee directory/detail stay read-only. Defer stored-session, refresh, role/password gates and account/role editors. Keep OPEN-READ-ORDER explicit. Existing source baseline/legacy routes must remain visible until their replacement is implemented; deferred features do not count as missing Phase 1 work.

2. **Replace the auth slice and its frontend consumers together.** Define Login/AuthResult/CurrentUser, AccessProof/CurrentAuthority and proposed AuthUsecase/AuthRepository/AuthSerializer methods first. Implement POST /staff/auth/login and GET /staff/auth/me, encoded bcrypt verification, configured finite JWT expiry, basic login throttling and current active-account/single-role/PA-assignment reads. Use the fixed permission mapping, rechecking resources within business writes. Remove legacy session/refresh/renew/logout/role/password routes and internal initialization from the Phase 1 composition; do not leave a cookie-auth fallback. Adapt auth configuration so CSRF/recovery/gateway keys are no longer required for this flow. Frontend retains token/expiry/user in memory, uses Bearer, clears private state on logout/expiry, requires login after reload, and disables deferred role/password/editor routes. Test wrong/expired tokens, algorithm/issuer/audience, inactive account, missing/multiple roles, database failure, direct scope denial and manual role/assignment changes. Exercise ordinary login/reload/expiry/local logout; do not add refresh, cross-tab rotation or idle-timer work. Operator account/role setup is a separate explicit database action, not part of this contract revision.

3. **Align shared transport and catalogs.** Fix D57/D58 rejected paths/error-code mapping and string-array fieldErrors. Adapt Room objects/roomId and attachmentsEnabled in frontend consumers. Add the authorized staff catalog with one request for relevant selectors. Verify malformed IDs/queries/unknown fields, safe errors and wrong-role responses. Current source HTTP captures do not prove the new Phase 1 auth behavior.

4. **Implement the visit aggregate and public creation/recovery.** Add the selected visit/detail/visitor/roster/reference/outbox schema that is still absent. Implement pending public creation, idempotent replay/recovery, public lookup/history and before-start cancellation with atomic audit/outbox/outcome. Test pair/restricted denials, validation, concurrent same/changed references, delayed create after closure, restart/lost response and rollback. Keep new optional uploads disabled.

5. **Implement authorized staff reads, creation and decisions.** Keep typed list/dashboard/reception reads and independent detail. Scope and project before search/count/page/metrics, using one consistent snapshot. Add standard/restricted create, approve/reject/reschedule/update/cancel with existing version/resource-lock/field-policy rules. Align Pending reschedule, stable room IDs, text bounds and response correlation. Verify direct API privacy/scope, empty/out-of-page results and concurrent scheduling/version conflicts. No per-card/note/dashboard table or editable permission policy is required.

6. **Implement reception and QR attendance.** Keep manual/QR resolve read-only, then explicit check-in/checkout commands with matching current credentials/version. Test inclusive check-in windows, replacement/revocation, parallel scanners, duplicates, prior-day late checkout and consumed/nonrevoked QR behavior. Keep restricted arrival data separate from ordinary reception caches. Camera images stay local.

7. **Complete read-only administration, scoped reports and SMTP settings.** Implement employee page/detail only; no account create/edit/role/assignment/password APIs. Remove the directory parser's deferred password metadata and hide editor controls. Existing profile columns already exist. Reuse report summary for analytics/logs, ordinary-only scope and revision-bound CSV export. Implement safe SMTP descriptors/configuration and outbox delivery using the selected secret/TLS rules; test secret non-disclosure, revision/count consistency and worker retry/restart. Roles and permission policy editors stay deferred.

8. **Implement optional private files only with the owning capability.** Preserve stage/replay/ownership/token/link/cleanup and authorized view/download invariants. Keep capability disabled until verified content, private access and cleanup work. Do not relax file privacy/ownership in order to simplify authentication. Production provider/scanner selection remains a release decision.

9. **Close active gaps and verify the release.** Update the source baseline deliberately with actual code changes, then regenerate current-binary docs. Run baseline and strict checks against Phase 1, real isolated PostgreSQL tests and browser flows for visitor plus each fixed role. Verify login throttling, token expiry/local logout, manual role changes, restricted privacy, scheduling and SMTP/file gates. The Phase 1 build must expose no source-only identity routes. Deferred session/account-role features do not block this gate; active OPEN-READ-ORDER and actual implementation gaps do.
