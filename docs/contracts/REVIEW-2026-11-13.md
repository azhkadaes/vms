The 48 feature rows now name actual dropdowns, dialogs, cards, tables, checkboxes and actions, with per-operation field-use descriptions. Current frontend mismatches remain visible alongside each binding. Shared catalog, dashboard/list/reception and reporting consumers remain shared; local printing, camera frames and static content add no endpoints. ## Phase 1 simplified-auth revision

User-approved scope: basic email/password login, one fixed-expiry Bearer access token, current database-authorized user, manually assigned single roles including initial Super Admin, fixed backend role permissions, and local-only logout. Stored sessions, refresh/rotation/recovery, idle renewal, auth cookies/CSRF bootstrap, role switching and password workflows are deferred. Employee page/detail are retained as read-only; employee/account/role/assignment mutation and role-policy UI are deferred.

The current target has 29 operations: two new /staff/auth/login and /staff/auth/me operations plus 27 retained business/read operations. Only public catalogs currently match a registered target route. Seven existing identity routes remain in the unchanged source and must be replaced/removed, not counted as new auth support. source-baseline.json freezes current route/schema/runtime evidence; it is not an alternative target. Swagger generation and validation explicitly distinguish it from canonical Phase 1.

AuthResult contains accessToken/tokenType/accessExpiresAt/user; CurrentUser has no lifecycle/gate fields. No new numeric token lifetime is invented: positive finite lifetime is required server configuration, and accessExpiresAt equals the token expiry. Roles/permissions/PA assignments are checked from the current database on every request, with relevant resource checks repeated in write transactions. The fixed mapping follows the existing frontend role vocabulary minus deferred role/audit administration; Super Admin receives no automatic ordinary-visit decision/document access.

Phase 1 explicitly supersedes the earlier auth/lifecycle/policy decisions while retaining schedule/state/version/public-pair/restricted-projection/idempotency/notification rules. OPEN-LOGOUT-PROOF is deferred because there is no server logout/cookie branch; OPEN-READ-ORDER remains active. Lifecycle-only gaps do not block Phase 1. DB-PROFILE was corrected against source: existing SQL already contains the profile columns, so no duplicate migration is needed.

This revision changes docs, schemas, examples, traceability, proposed interface mappings and docs/check tooling. It does not implement either auth route, change application/frontend behavior, alter database contents/migrations, create credentials or deploy anything.
