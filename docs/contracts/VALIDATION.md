Reviewed 19 November 2026 WITA, ticket 03 (contract pipeline rebase). The machine-readable contract now tracks the 40-operation [operation reference](FRONTEND-DRIVEN-REST-API-2026-11-16.md) and its numbering. The earlier Phase 1 gate (29 operations, [BACKEND-OPENAPI-2026-11-12.json](../BACKEND-OPENAPI-2026-11-12.json)) is superseded; its record is described at the end.

## Artifacts

| File | Role |
| --- | --- |
| [manifest.json](manifest.json) | All 40 operations: number, ID, method, path, summary, owning ticket and status (`implemented` or `missing`). Implemented operations add their handler, the delegation calls it must keep, the usecase method and the request/response DTOs. Also the reviewed Go interface and DTO inventory, the migration table inventory, frontend request call sites mapped to operation numbers, known consumer gaps and source corrections. |
| [source-baseline.json](source-baseline.json) | OpenAPI 3.1.1 shapes of the implemented operations as the server returns them: paths, schemas, examples, the error body, the error-code catalogue (`x-error-catalogue`) and one runtime expectation per contract capture. |
| `check.py` | The gate. `--backend DIR` picks the checkout (a worktree checks itself), `--contracts DIR` checks a draft copy of the two JSON files, `--write-inventory` refreshes the Go and migration inventory. |
| `inspect-go.go` | Go AST inventory: routes, handlers, calls, interfaces, DTO fields, the failure catalogue and the error middleware's status defaults. Never loads configuration or a database. |
| `check-consumers.mjs` | Runs the frontend's own parsers and HTTP client against the baseline examples, and lists every frontend request call site. |
| `invariants.py` | Migration table inventory and local Markdown link check. |
| `backend/docs/openapi.json` | Served OpenAPI, generated by `make swagger` from the manifest and baseline. |
| [validation-results.json](validation-results.json), [strict-validation-results.json](strict-validation-results.json) | Latest results. |

The per-slice procedure for registering an operation is in [the Go conventions](../BACKEND-GO-CONVENTIONS.md), section 8, step 4.

## What the gate checks

| Check | Rejects |
| --- | --- |
| Manifest against the operation reference | Any difference in number, method or path from the `### NN. METHOD /v1/path` headings; duplicate IDs; a missing operation carrying a source mapping; a request call mapped to an unknown operation |
| Source baseline | OpenAPI 3.1 meta-schema or local-ref errors; operations other than the implemented ones; ID or number drift; an error status without its condition or shared error response; examples that fail their schemas; error examples that do not use the catalogue message |
| Go source | Routes that differ from the implemented operations (an unregistered route fails); a route bound to another handler; a handler that stops delegating; a missing usecase method; DTO fields, including nested DTOs, that disagree with the schemas on presence, `omitempty` or type; interface or DTO inventory drift; a failure catalogue that differs from `x-error-catalogue`; status defaults outside it |
| Served OpenAPI | `docs/openapi.json` not regenerated after a manifest or baseline change |
| Migrations | Any table added, removed or renamed without updating the inventory |
| `--runtime` | A capture whose status, schema, code, catalogue message, `fieldErrors` or headers drift from the baseline; captures without expectations; an implemented operation without a successful capture |
| `--consumers` | A new or fixed frontend gap; a new or changed frontend request call site not mapped to an operation |
| `--strict` | Exit 1 while any operation is missing or any known gap remains |

Ten deliberate drift mutations run on every check and must be rejected: unregistered route, removed route, changed and new interface, renamed DTO field, changed error message, stale served OpenAPI, renumbered operation, implemented operation marked missing, and a hidden `IF NOT EXISTS` table.

## Integrated backend result, 20 November 2026

The backend implements all 40 operations. The contract check validated 115 HTTP responses and 14 frontend parser checks, with no missing backend operations. The Go test suite, static checks, and integration suite passed against a disposable PostgreSQL 18 instance. The integration suite exercised the migration cycle separately from the runtime database.

The initial backend release reported four adapter gaps. The Docker frontend update resolved the measured Bearer, catalog parsing, login token and role token gaps. See [the strict result](strict-validation-results.json) for the latest checks. These checks do not cover every remaining workflow in the [frontend adapter tickets](../specs/frontend-adapter-2026-11-19/map.md).

## Ticket 03 result, 19 November 2026

Run from the ticket 03 worktree, after merging ticket 02, with `python ../docs/contracts/check.py --backend . --runtime --consumers`. Ticket 02's queued contract updates are applied: its two new interfaces, op 36's 403, the A-18 captures and the pending-session error example.

| Check | Result |
| --- | --- |
| Operations | 40 in the manifest. Eight implemented: 01, 32–36, 39, 40. The other 32 are missing, each with its owning ticket. |
| Source | 8 routes, 17 interfaces, 12 DTOs (including `dto.Optional`, with no JSON fields), a 24-code error catalogue that equals `pkg/helper/failure/catalogue.go`, and 22 migration tables from `202611180002_create_vms_kedeputian.sql` to `202611180023_create_support_refresh_recovery.sql` |
| Runtime | 16 Fiber captures through the exported route registrations (public admission, StaffAuth with a signed Bearer token, the A-18 stage gate), all accepted, no known runtime gaps. Unknown query and unknown JSON field are 400 `invalid_query_parameter` / `invalid_request` without `fieldErrors`. A wrong current password on op 36 is 422 `validation_failed` with `fieldErrors.currentPassword`. An expired logout (op 35) is 401 `unauthenticated`, as the operation reference specifies. Changing the password while a role selection is pending (op 36), or selecting a role while a password change is pending (op 34), is 403 `forbidden` with the pending-session message (A-18, ticket 02). |
| Consumers | 7 parser checks pass, including "wrong current password keeps the session". 34 request call sites are mapped. Four known gaps remain for the frontend adapter, which is out of scope for the backend spec: `authenticated-request-missing-bearer`, `catalog-room-objects`, `login-token-result-unconsumed`, `role-token-result-parsed-as-session`. |
| Strict | Fails, as expected, on the 32 missing operations and four consumer gaps |
| Unregistered route | Demonstrated: adding `GET /v1/public/catalogs/extra` to the public router failed the check with "Source routes differ from the implemented manifest operations: GET /v1/public/catalogs/extra". Reverting it restored a pass. |

Limitations: no live database, migration, container, server start or deployment is exercised. Runtime captures use injected usecases, so they prove HTTP decoding, status, error body and serialization, not authorization or PostgreSQL behaviour.

## Phase 1 record

The superseded Phase 1 reference can be rebuilt from the repository root with `python docs/contracts/render.py --write`. The renderer uses the tracked `API-CONTRACT.md` as its template, together with [the archived Phase 1 manifest](phase1-manifest-2026-11-13.json), `examples.json` and the Phase 1 OpenAPI. Git ignores the six generated companion pages. Run `python docs/contracts/render.py` after generating them to verify the local copies. The [current API reference](FRONTEND-DRIVEN-REST-API-2026-11-16.md) is covered by `check.py`.
