- Contract: separate typed summary and export repository methods and synthetic GET endpoints. Summary contains range/status/scope/generated time/revision, counts and total, without visitor rows. Export rechecks report/read/export scope and revision before returning summary CSV. A changed aggregate/scope requires refresh before export.
- Scope: preserve existing ordinary-record scope for PA (assigned non-VIP officers), Protocol (existing authorized ordinary read scope), and any explicitly authorized Receptionist (its attendance lifecycle scope). Super Admin may receive ordinary organizational aggregates independently of its restricted-only detail access. All roles still need report permission; export additionally needs its own permission. Authorization precedes validation/counts.
- Display: use existing six lifecycle statuses plus derived Terlewat/Missed as mutually exclusive display groups, consistent with booking filters. This does not add a stored lifecycle status. Include explicit range and scope. Zero follows a validated successful response; initial/error/denied/offline data is not represented by zero. An older successful result may remain clearly marked after a temporary refresh failure, with export disabled.
- Filter defaults: current WITA calendar month and all statuses are preview defaults, not organization-approved production defaults. Native date fields support history/future dates; enforce valid ordered dates and at most 366 inclusive days as a preview bound. Keep filters in URL; local edits require Apply and disable export until applied.

Extract Reports from Settings so employee/role/integration preview pages no longer subscribe to booking rows. Keep shared buttons/feedback and existing visual direction; no new asset/dependency.
- Three performance questions: request only aggregates, once per applied filter; avoid record scans/export in the browser; aggregate authoritatively in the synthetic service and future backend. No report polling, worker, chart library or startup schema import. Focus/return/manual refresh use the query layer.
- Accessibility/states: labeled date/status fields, linked errors/focus, semantic count table, zero/refresh/denial feedback, disabled unavailable export, narrow responsive filter controls, download status and keyboard operation. Preserve other unselected directory/navigation gaps.
- G09: update current requirements/plans to a single server-assigned active role per account and role-bound permissions/assignments/audit. No production role switch or union of role permissions. Keep the clearly marked development test-role selector; production session integration remains pending and must not infer a role from array ordering.

## Implementation and backend handoff

- `packages/data/src/reports.ts` owns typed filters, response validation, scope/count policy and summary CSV. `Reports.tsx` owns the report route UI; it is loaded separately from employee/role/integration settings. Those settings no longer fetch booking rows just to render their page.
- GET `/__preview/reports/summary` accepts from/to/status and returns only validated filters, authorized scope, generatedAt, revision, canExport, display-status counts and total. There are no visitor rows, codes, contacts, ID fields or restricted events in this contract. Report read permission is independent of individual booking permission.
- GET `/__preview/reports/export` additionally requires export permission and the displayed revision. The service recomputes current scope/counts and returns 409 if the displayed revision no longer matches. The UI refreshes and requires another explicit export. CSV contains range, scope, status and count, with no individual visitor data. Revoked read/export rights are enforced again at the endpoint; refreshed canExport makes a permitted read-only report explicit.
- Default scope is existing permitted ordinary visits for PA/Protocol; Reception has no report permission by default and would retain its attendance scope if explicitly granted one. Admin organization aggregation is independent of its restricted-only detail scope. Restricted records are removed before aggregation for every role.
- Report counts use mutually exclusive display groups: six stored statuses plus derived Missed for Approved visits past their arrival end. No stored seventh status is introduced. Filters are URL state; unapplied changes disable refresh/export. Invalid ranges focus their field. Default current WITA month and at most 366 inclusive days are preview defaults, not approved production capacity/period rules.
- Initial errors, denied access, malformed responses and offline pending data are unavailable rather than zero. A previously successful summary can remain clearly marked after temporary refresh failure; export is disabled until fresh success. Denial hides cached totals. Response validation rejects inconsistent totals, unexpected record fields and a mismatched requested period/status.
- G09 removes production multi-workspace switching and permission unions. One canonical server-assigned active role must control session, scopes and audit; authorized administrative reassignment refreshes/invalidates session/private cache. The development fixture selector remains explicit. Existing production session parsing/role-state hazards in audit A2-06 still require the new backend integration; a documentation choice does not certify that adapter.

The future backend must perform authorization and scope before database aggregation, with consistent snapshot/revision checks at export. The SHA revision is a freshness check, not a credential. Real session authentication, data persistence, report schema/defaults/capacity and detailed audit/visitor export remain future work. No existing backend repository supplies these contracts.
